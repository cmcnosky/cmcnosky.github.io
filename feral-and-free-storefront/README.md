# Feral & Free | catalog storefront prototype

This is an independent, non-transactional design build, not the Feral & Free merchant's official store. This branch is source code, not a GitHub Pages deployment. No merchant inventory, credentials, buyer information, or checkout are included.

## Run locally

From this directory, run `python -m http.server 8712` and open `http://localhost:8712/`. Add `?demo=1` to see clearly labeled fictional products and test browsing. The empty `catalog.json` deliberately gives shoppers links to the live marketplaces. It is not evidence of an empty seller inventory. Run `python -m unittest -v test_prepare_catalog.py` for importer checks.

## Connect owner-approved inventory

1. Obtain the sellers' source inventory and their approved photos and copy, plus a stable public-safe key per physical item and the confirmed active listing URL on each marketplace. Include any marketplace-exclusive inventory. Start with verified matching in Nifty's inventory manager if the owners use it; its documented active inventory CSV includes internal cost data and is not documented as a complete publishable feed. Do not pull or republish platform-catalog content as if it were the sellers' own. Do not publish raw exports or use public repository history as an inventory database.
2. Reconcile active counts separately per marketplace, spot-check sizes/condition and exact links, de-duplicate by verified stable key (not title or photo similarity), and omit links that are inactive or ambiguous. Keep private SKU notes/metadata/photos separate. Store approved listing photos as optimized, renamed files below `assets/catalog/`; remove EXIF or other private metadata before publishing.
3. Use `catalog-template.csv` as the header template. Normalize the owner file to UTF-8 CSV with headers `id,status,title,description,category,brand,size,condition,image,images,price,currency,listed_at,ebay,poshmark,mercari`. The core fields and the three marketplace-link headers are required; a row needs just one verified link. Separate additional photo paths in the optional `images` field with a pipe (|). Blank optional fields are safe; leave price blank if no single reliable item price applies across presented links. A comma, quote, or newline in a description must be RFC 4180-quoted by the export tool. Provide plain-text descriptions, not listing HTML. Use U.S. marketplace URLs and actual ISO timestamps with timezones.
4. Run `python prepare_catalog.py /path/to/private-normalized.csv --as-of '2026-11-23T01:00:00Z'` using the true source timestamp, not that example or the time a file was published. For live use, repeat from a permitted machine-readable source on commerce-compatible hosting with secure secrets and refresh the catalog regularly; the browser hides listings after six hours without fresh confirmation. Seller links are still the authority for final price, availability and checkout. A single CSV is not real-time synchronization.
5. Test a complete seller-approved snapshot and a sold-item removal before launch. Track freshness and reconcile unexpected stock declines or unmatched links; use marketplaces alone if there is no maintainable inventory feed. Use GitHub for source, not production e-commerce hosting. Never put card entry or secret keys in this frontend.

Reference: [Nifty exports](https://docs.nifty.ai/analytics/insights-and-reports), [Nifty inventory manager](https://docs.nifty.ai/inventory-management/inventory-manager), [eBay Seller Hub Reports](https://export.ebay.com/en/services-tools/seller-hub/seller-hub-reports/), [eBay API public display rules](https://developer.ebay.com/support/api-license-agreement), [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
