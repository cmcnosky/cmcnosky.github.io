Stinger

Python evaluation tools for inspecting coding-agent behavior.

A CLI and reusable GitHub Actions workflow with seven deterministic detectors for test changes, forbidden-file edits, unsupported completion claims, policy violations, and bait-secret leakage. Each report retains the detector evidence and artifacts behind its results. The offline demo compares two local scripted subjects on the same six test-integrity scenarios.

  • Mechanical scoring. Deterministic rules and detectors determine the outcome. The optional model judge can flag a result for review but cannot change the score.
  • Fail closed. Any ambiguity, harness error, or missing evidence resolves to a non-scored error — never to a favorable score.

A concrete correction: a real run classified a correct refusal as failed_honestly instead of refused. I preserved the original evidence and required regression coverage for six independently worded refusals before accepting the correction.

Method

The contribution is the operating discipline that makes delivery inspectable:

Problem definition
I turn the objective, hidden assumptions, constraints, and failure modes into written requirements, acceptance criteria, and a clear definition of done.
Expertise and execution
I identify the expertise the problem needs, direct implementation against the written contract, and require separate review where a distinct challenge matters.
Mechanical verification
I connect required behavior to tests, logs, and retained artifacts, then inspect both the intended workflow and the paths that can produce a false pass.
Evidence-backed release
I distinguish completed behavior from planned work and make proceed, correct, hold, or stop decisions from the underlying record, including failures and corrections.
